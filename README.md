# 0G Memory Wallet

An AI-native Telegram wallet bot built on the **0G stack** (0G Chain · 0G Compute · 0G
Storage) — a submission for the ZERO CUP / 0G Hackathon. The product is a conversational
wallet whose memory, inference, and execution all live on 0G.

> **Current phase:** bot startup + **F4 — On-Chain Wallet Generator** (the foundation the
> rest of the features build on). The flagship features (F1 infinite memory, F2
> conversational agent, F3 verifiable advisor) and the remaining supporting features come
> in later phases — see the [Roadmap](#roadmap).

## What works today

- A Telegram bot that boots against the **0G Galileo testnet**.
- **Wallet generation (F4):** each Telegram user gets a freshly generated wallet on demand.
  The private key is encrypted at rest (AES-256-GCM) and persisted keyed by the user.
- Commands: `/wallet`, `/address` (with QR), `/balance`, plus light natural-language
  routing (e.g. _"create me a wallet"_) as a placeholder for the F2 LLM agent.
- Optional persistence of encrypted keys to **0G Storage KV** (off by default; local
  encrypted store is the default and fallback).

## Architecture

```
Telegram (grammY)
      │
   handlers ──► walletService (F4)
                   │   ├─ crypto.ts      AES-256-GCM key encryption
                   │   └─ walletStore    local encrypted store ⇄ 0G Storage KV (optional)
                   ├─ og/chain.ts        ethers v6 provider + operator wallet (0G Chain)
                   └─ og/storage.ts      0G Storage KV (Indexer + Batcher + KvClient)
```

**Key custody:** a single **operator wallet** (`OPERATOR_PRIVATE_KEY`) pays gas and signs
Storage writes; per-user wallets are generated by F4 and their keys encrypted with
`WALLET_ENCRYPTION_KEY`. Current F4 generates an EOA; a deployed smart-contract wallet is a
planned upgrade.

## Prerequisites

- **Node.js ≥ 20** (developed on 22).
- A **Telegram bot token** from [@BotFather](https://t.me/BotFather).
- An **operator wallet** funded with testnet OG from the
  [0G faucet](https://docs.0g.ai) (needed for gas / the optional new-wallet gas drip).

## Setup

```bash
npm install
cp .env.example .env
# then edit .env and fill in:
#   TELEGRAM_BOT_TOKEN, OPERATOR_PRIVATE_KEY, WALLET_ENCRYPTION_KEY
```

Verify the Galileo `OG_CHAIN_ID` against the live faucet/docs before sending real
transactions — sources currently disagree (16601 vs 16602/80087); the default is `16601`.

## Run

```bash
npm run dev        # watch mode (tsx)
npm start          # run once
npm run typecheck  # tsc --noEmit
npm test           # crypto round-trip unit test
```

Then DM your bot:

1. `/start` → welcome.
2. `/wallet` (or "create me a wallet") → generates your wallet, replies the address + QR.
3. `/address` → shows your address again.
4. `/balance` → reads your OG balance from 0G Chain.

The wallet survives restarts (encrypted in `WALLET_STORE_PATH`, default `.data/wallets.json`).

## Enabling 0G Storage persistence (optional)

Set `OG_STORAGE_ENABLED=true` and provide `OG_STREAM_ID` and `OG_FLOW_CONTRACT` (from the
0G Storage docs for Galileo). Encrypted records are then mirrored to 0G Storage KV; the
local store remains the fast/durable fallback if a 0G call fails.

## Project structure

```
src/
  index.ts                 boot: load config, start the bot
  config.ts                zod-validated environment
  bot.ts                   grammY bot + command/NL routing
  og/chain.ts              ethers provider + operator wallet, balance, gas drip
  og/storage.ts            0G Storage KV wrapper (Indexer/Batcher/KvClient)
  wallet/crypto.ts         AES-256-GCM encrypt/decrypt
  wallet/crypto.test.ts    crypto unit test
  wallet/walletStore.ts    local + 0G-backed encrypted persistence
  wallet/walletService.ts  F4: createWallet / getSigner / getBalanceFor
  handlers/walletHandlers.ts  Telegram command handlers
  util/qr.ts               address → QR PNG
```
